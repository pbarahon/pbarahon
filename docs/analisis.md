
# Fase 1: Análisis

## 1. Objetivo

Analizar diferentes perfiles y repositorios de GitHub para identificar buenas prácticas de presentación, organización y documentación, que sirvan como referencia para desarrollar mi portafolio digital.

## 2. Perfiles de referencia

Se seleccionaron tres perfiles de la colección [Awesome GitHub Profile README](https://github.com/abhisheknaiidu/awesome-github-profile-readme).

- [Ing](https://github.com/innng/innng)
- [Alex Martin](https://github.com/AlexMartinFR/AlexMartinFR)
- [Martin Heinz](https://github.com/MartinHeinz/MartinHeinz)

### Tabla comparativa

| Criterio | Ing | Alex Martin | Martin Heinz |
|---|---|---|---|
| Presentación | Creativa y breve, con estilo manga. | Personal, sencilla y original. | Profesional y directa. |
| Estructura | Ilustración lateral y contenido compacto. | Presentación y crucigrama visual. | Secciones claramente organizadas. |
| Habilidades | Describe sus intereses técnicos. | Combina intereses personales y profesionales. | Utiliza insignias y herramientas. |
| Proyectos | Pocos proyectos explicados en el README. | Enlaces a proyectos y contribuciones. | Tarjetas con enlaces a repositorios. |
| Contacto | Información profesional limitada. | Enlaces a redes sociales. | Enlaces profesionales y sitio personal. |
| Accesibilidad | Depende bastante de imágenes y animaciones. | Su diseño visual puede dificultar la lectura móvil. | Contenido ordenado, aunque utiliza imágenes externas. |

Las observaciones sobre accesibilidad son preliminares y no corresponden a pruebas técnicas.

## 3. Análisis de repositorios

También se revisaron tres repositorios para conocer cómo documentan sus proyectos.

| Repositorio | Aspectos positivos | Aspectos por mejorar |
|---|---|---|
| [Crabby](https://github.com/unsafers/crabby) | Explica funcionalidades, instalación y comandos. | Tiene apartados de documentación pendientes. |
| [Alfred WordReference](https://github.com/alexmartinfr/alfred-wordreference) | Incluye instrucciones, ejemplos y créditos. | Su documentación puede resultar extensa. |
| [Python Project Blueprint](https://github.com/MartinHeinz/python-project-blueprint) | Organización de carpetas, licencia y pruebas. | Podría tener una introducción más sencilla. |

## 4. Revisión de mis proyectos

Se seleccionaron tres trabajos académicos para destacar en el portafolio:

1. **Feria del Cacao:** proyecto colaborativo donde participé en la investigación y recopilación de información.
2. **dawm-cv:** práctica académica de HTML y CSS para elaborar un currículum web.
3. **Proyecto POO:** repositorio académico de Java relacionado con la programación orientada a objetos.

Se identificó que algunos repositorios necesitan mejorar sus descripciones y documentación. Por ello, el portafolio incluirá explicaciones y enlaces para facilitar su comprensión.

## 5. Requisitos del portafolio

### Requisitos funcionales

- Presentar información académica y profesional.
- Mostrar al menos tres proyectos con descripciones y enlaces.
- Identificar las tecnologías y herramientas utilizadas.
- Incluir medios de contacto profesional.

### Requisitos no funcionales

- Mantener un diseño sencillo y visualmente atractivo.
- Facilitar la lectura y la navegación.
- Permitir su consulta desde diferentes dispositivos.
- Mantener enlaces funcionales.
- Facilitar futuras actualizaciones del contenido.

## 6. Conclusión

Después de revisar los perfiles, decidí combinar una presentación organizada con una identidad visual más personal.

El perfil de Ing fue la principal referencia estética por su ilustración de estilo manga. Los otros perfiles ayudaron a identificar formas de organizar mejor la información, las tecnologías y los proyectos.

El resultado buscado es un portafolio que refleje mi formación como estudiante de Computación y que pueda seguir actualizando a medida que desarrolle nuevos proyectos.
